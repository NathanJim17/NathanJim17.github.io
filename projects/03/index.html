PROJECT 03 · PART A
Flow Models for
Image Generation
nathanjim17.github.io
This project uses a pretrained text-to-image flow model, PixNerd, to denoise, generate and edit 512×512 images without any training. A flow model learns a velocity that moves an image from pure noise at t = 0 to a clean image at t = 1. Part 1 looks at what that velocity does on a noisy photo and builds an Euler sampler. Part 2 adds classifier-free guidance. Part 3 uses the sampler for image editing, visual anagrams and hybrid images.
PART 1.1 Constructing noisy training inputs

A noisy input is a straight-line mix of Gaussian noise ε and the clean image x1, xt = (1−t)ε + t·x1. At t = 0 it's pure noise and at t = 1 it's the clean image. I sampled one noise tensor with seed 180 and reused it at all three times, so Sections 1.2 to 1.5 all start from the same inputs. 

def interpolate(image, noise, t):
    xt = (1-t)*noise + t*image
    return xt

PART 1.3 One-step denoising

The model predicts a velocity vθ(xt, t, c) that points toward the clean image. Taking one full step to t = 1 gives an estimate x̂1 = xt + (1−t)vθ. The prompt here is "a high quality photo". 

def one_step_denoise(x, t, condition, predict_velocity):
    v = predict_velocity(x, t, condition)
    x1_hat = x + (1-t)*v
    return x1_hat

PART 1.5 Iterative denoising with Euler sampling

Instead of one big step, Euler sampling takes many small ones, xt+h = xt + h·v(xt, t), recomputing the velocity each time. With h = 0.02, starting at t = 0.50 takes 25 steps. The last step is shortened if needed so it ends exactly at t = 1. 

@torch.inference_mode()
def euler_sample(x_start, t_start, step_size, velocity):
    t = t_start
    x_th = x_start
    states = [(t, x_th)]
    while t < 1:
        h = min(step_size, 1-t)
        x_th = x_th + h * velocity(x_th, t)
        t += h
        states.append((t, x_th))
    return x_th, states

PART 2.1 Classifier-free guidance

CFG runs the model twice per step, once with the prompt and once with an empty prompt, and pushes past the conditional prediction, vcfg = vc + w(vc − vu). At w = 0 it's the plain conditional velocity. I used w = 7 and the same five noises as 1.6. 

def cfg_velocity(x, t, condition, w, predict_velocity, null_condition=''):
    v_c = predict_velocity(x, t, condition)
    v_u = predict_velocity(x, t, null_condition)
    return v_c + w*(v_c - v_u)

PART 3.1 Image-to-image editing

To edit a photo, I add noise up to a start time with interpolate and then run the CFG Euler sampler back to t = 1 with "a high quality photo". A low start time means more noise, so the model has more freedom to change the image. All edits use the same noise (seed 180), h = 0.02 and w = 7. 

def edit(image, noise, t_start, condition, predict_velocity, w=7, step_size=0.02):
    x_start = interpolate(image, noise, t_start)

    def velocity(x, t):
        return cfg_velocity(x, t, condition, w, predict_velocity, null_condition)

    final, _ = euler_sample(x_start, t_start, step_size, velocity)
    return final

PART 3.3 Visual anagrams

A visual anagram looks like one thing upright and another when rotated 180°. At every Euler step I get the CFG velocity for prompt a on the image, and the velocity for prompt b on the rotated image, rotated back. Averaging the two pushes the image toward a picture that works both ways. Both prompts share the same style so the two readings can blend. 

def visual_anagrams(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
  def velocity(x, t):
    v1 = cfg_velocity(x, t, condition_a, w, predict_velocity, null_condition)
    v2 = rotate180(cfg_velocity(rotate180(x), t, condition_b, w, predict_velocity, null_condition))
    return (v1 + v2) / 2

  final, _ = euler_sample(noise, 0, step_size, velocity)
  return final

PART 3.4 Hybrid images

Like the hybrids in Project 02, but generated instead of combined from two photos. At every Euler step I take the CFG velocity for both prompts on the same image, keep the low frequencies of the far prompt and the high frequencies of the close one. The low-pass is a Gaussian blur with σ = 16 (kernel 265). Up close you see the texture of prompt b, and from far away only the coarse shape of prompt a is left. 

def make_hybrids(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
  def velocity(x, t):
    v1 = cfg_velocity(x, t, condition_a, w, predict_velocity, null_condition)
    v2 = cfg_velocity(x, t, condition_b, w, predict_velocity, null_condition)
    return lowpass(v1) + (v2 - lowpass(v2))

  final, _ = euler_sample(noise, 0, step_size, velocity)
  return final

What didn't work

My first two pairs only showed the close prompt at any size. A Gaussian with σ = 16 keeps only shapes around 100 pixels and larger, so the far prompt can only contribute a rough silhouette. A hand is defined by its fingers and a panda by its eye patches and ears, and all of those are thinner than that. The bamboo also came out green, and since color is low frequency it took over the far view too. Subjects with big bold features, like a mane or a head outline, work much better.

PROJECT 03 · PART B
Flow Matching
from Scratch
nathanjim17.github.io
In Part B I build and train my own models on MNIST. Part 1 trains a UNet to remove noise in a single step, and shows why that can't generate new digits. Part 2 trains a flow matching model that predicts the velocity from noise to data, first conditioned on time only and then on time and the digit class, with classifier-free guidance.
PART B 1.1 Implementing the UNet

Each basic op is a convolution followed by BatchNorm and GELU. Conv keeps the size, DownConv halves it with stride 2 and UpConv doubles it with a transposed convolution. Two downsampling blocks take the 28×28 input to 7×7, Flatten averages that to 1×1, and Unflatten brings it back. On the way up each block is concatenated with the matching skip connection. With D hidden channels the widths go D, D, 2D at the bottleneck, then back to D. 

class Conv(nn.Module):
    def __init__(self, in_channels, out_channels):
        super().__init__()
        self.conv = nn.Sequential(
            nn.Conv2d(in_channels, out_channels, kernel_size=3, stride=1, padding=1),
            nn.BatchNorm2d(out_channels),
            nn.GELU()
        )

# UnconditionalUNet.forward
conv1 = self.ConvBlock1(x)                 # D,  28x28
down1 = self.DownBlock1(conv1)             # D,  14x14
down2 = self.DownBlock2(down1)             # 2D, 7x7
bottleneck = self.unflatten(self.flatten(down2))
up1 = self.UpBlock1(torch.cat((bottleneck, down2), dim=1))   # 4D -> D
up2 = self.UpBlock2(torch.cat((up1, down1), dim=1))          # 2D -> D
output = self.ConvBlock2(torch.cat((up2, conv1), dim=1))     # 2D -> D
return self.conv2d(output)

Every output is the same blurry blob no matter what noise goes in. It looks like a 0, 8 and 9 drawn on top of each other. PART B 2.1 to 2.3 Time-conditioned flow matching

Instead of jumping straight to a clean digit, the UNet now predicts the velocity x1 − x0 at a noisy point xt = (1−t)x0 + t·x1, the same idea as the pretrained model in Part A. The time t is embedded with two FCBlocks that scale the bottleneck and the first upsampling block. I trained it for 10 epochs with D = 64, batch size 64 and Adam starting at 1e-2, with an exponential schedule that decays the learning rate to 1e-3 by the end. 

def time_fm_forward(unet, x_1, num_ts):
    t = torch.rand(x_1.shape[0], device=x_1.device)
    x_0 = torch.randn_like(x_1)
    t_view = t.view(-1, 1, 1, 1)
    x_t = (1 - t_view) * x_0 + t_view * x_1
    return F.mse_loss(unet(x_t, t), x_1 - x_0)
training loss, 10 epochs

The loss starts very high, around 13, because the untrained network's outputs are far from the target velocity. It drops below 1 within the first few hundred steps and then slowly settles. The spike squashes the rest of the curve, so the slow improvement after that is hard to see on this scale.

PART B 2.4 to 2.6 Class-conditioned flow matching

To control which digit comes out, the UNet also takes the class as a one-hot vector. Two more FCBlocks embed it, and the class scales each feature map while the time shifts it. 10% of the time during training the class vector is set to zero, so the same model also learns an unconditional velocity. At sampling time I combine the two with classifier-free guidance, u = uuncond + γ(ucond − uuncond) with γ = 5 and 300 Euler steps. 

# modulation inside ClassConditionalUNet.forward
unflatten = c1 * unflatten + t1
up1 = c2 * up1 + t2

# one Euler step of class_fm_sample, both passes in one batch
v_pred = unet(torch.cat([x_t, x_t]), c_double, t_double, mask_double)
v_cond, v_uncond = torch.chunk(v_pred, 2, dim=0)
v_gamma = v_uncond + guidance_scale * (v_cond - v_uncond)
x_t = x_t + v_gamma * dt

Removing the learning rate scheduler

The scheduler starts at 1e-2 and decays to 1e-3. Keeping 1e-2 the whole time would take steps that are too big near the end, so to compensate I used a constant learning rate of 1e-3, the value the scheduler ends at. Training is a little slower at the start but more stable, and with the same 10 epochs the results match the scheduled model. All 40 digits are readable and about as clean, with only slightly rougher edges on a couple, like the 8 in the first row and the 4 in the last.
